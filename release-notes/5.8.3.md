# Agent Session Pilot 5.8.3

## Telegram

- **One bot for several machines, through a relay.** A bot whose webhook goes to a relay (bot.json `relais`: `url`, `machine`, `prefixe`, `principale`) is now read there, never with `getUpdates`, which Telegram refuses while a webhook is set. The listener reading for the machine takes its share from the relay and acknowledges it. It also tells the relay which topics and project groups the machine holds, whenever they change and every 10 minutes. On a machine with a prefix (`pc`), sessions show as `pc-my-app`, and `pc-my-app: …` reaches them.
- `asp telegram relay` reads the relay for every session of the machine, as a launchd or systemd service. `asp telegram relay --sync` only declares the machine's topics and groups.
- The relay token is read from the Keychain on macOS (`[telegram] relay_keychain_service`) and from `relay-token` (mode 600) in the data folder on Linux.
- `asp telegram doctor` shows the relay's machines, when each one last read it, and what is waiting for them.
- `asp telegram setup` stops on a bot that already delivers to a webhook, and says why. ASP never removes a webhook: whatever relies on it would stop receiving.
