# Agent Session Pilot 5.8.10

## Telegram

- **Listeners update themselves.** When a new asp is installed, every `asp telegram listen` started with this version or later switches to it on its own, about 30 seconds later. It keeps its process and output, so the waiting session isn't woken, and messages already waiting are delivered first. Until now, each listener ran its old code until its next message, and `doctor` asked you to restart them one by one. `doctor` now reports only listeners that really run an older build.

## Auto-resume

- **Timeouts are resumed too.** When Claude Code stopped on "Stream idle timeout - no chunks received" or "408 Request timeout", asp treated it as a permanent error and left the session stopped. Both are passing network failures: asp now types "continue" once the API answers again, as it does for a dropped connection.

## Log

- **One entry, one line.** Hooks run as separate processes and write to the same log. Two hooks firing together could mix their lines (`[[17912354841791235484] ] …`). Each entry is now written in a single write, and a message that spans several lines (an API error, a notification) stays on one line.
- **The log no longer grows forever.** Past 10 MB, `asp.log` becomes `asp.log.1` and a new log starts. Only one previous log is kept.
